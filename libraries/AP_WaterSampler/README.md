# AP_WaterSampler — 水质采样驱动

本目录是 ArduPilot 的**水质采样机构**驱动。一个文件夹里装了三个互相独立的执行器，
由飞控的同一套采样流程串起来：

| 文件 | 内容 |
| --- | --- |
| `AP_WaterSampler.{h,cpp}` | 采样杆驱动 + **整套采样流程的状态机** |
| `AP_WaterValve.{h,cpp}` | 电磁阀（选 1 号瓶 / 2 号瓶）驱动 |
| `AP_WaterPump.{h,cpp}` | 水泵驱动（正转抽水 / 反转排水 / 停止） |
| `AP_WaterSampler_config.h` | 编译开关和所有默认值 |
| `README.md` | 本文件：参数表、接线、流程和排查 |

只有 Rover 编译这个库：

| 位置 | 内容 |
| --- | --- |
| `Rover/Parameters.h` | `AP_WaterSampler water_sampler;` |
| `Rover/Parameters.cpp` | `AP_SUBGROUPINFO(water_sampler, "WS_", 2, ParametersG2, AP_WaterSampler)` |
| `Rover/system.cpp` | `rover.g2.water_sampler.init();` |
| `Rover/Rover.cpp` | `SCHED_TASK_CLASS(..., update, 10, 100, 33)`，10 Hz |
| `Rover/wscript` | `'AP_WaterSampler',` |

三个执行器的分工：

| 执行器 | 作用 | 实现 |
| --- | --- | --- |
| 采样杆 | 有刷直流电机 + 螺杆 + 限位开关，把采样管放下去 / 收回来 | `AP_WaterSampler` + `AP_WaterPump` 的电机通道 |
| 电磁阀 | 两工位，选 1 号瓶还是 2 号瓶 | `AP_WaterValve` |
| 水泵 | 24V 白吸泵，正转抽水 / 反转排水 | `AP_WaterPump` |

采样杆的驱动器接受普通舵机 PWM：`< 1500` 伸出、`> 1500` 收回、`= 1500` 停止。
到达限位开关时驱动器自己断电，**飞控不需要限位反馈线**。

电磁阀和水泵都是**低电平触发**，用普通 GPIO 电平驱动，不是舵机 PWM。

## 一次采样的完整流程

地面站先写好**瓶号**和**容量**，再拉一下**触发通道**的上升沿，剩下全部由飞控跑完：

```
地面站写信箱(瓶号/容量) → 地面站拉触发上升沿 → 飞控自己跑完
① 选通瓶号            吸合/释放电磁阀，先给水一个去处
② 等 WS_VALVE_DELAY   默认 5s，等电磁阀动作到位
③ 采样杆回零 *        仅开机后第一次采样：给 1s 收回脉冲
④ 放下采样杆          1s 停 → 8s 动作 → 1s 停（共 10s）
⑤ 泵正转按容量抽水     容量 ÷ WS_FLOW_RATE，1000ml @10ml/s = 100s
⑥ 关泵                泵停，杆仍在下位
⑦ 等 WS_CLOSE_DELAY   默认 3s，让管路里的水稳定
⑧ 收起采样杆          1s 停 → 8s 动作 → 1s 停（共 10s）
⑨ 完成                阀保持不动，2 号瓶继续导通直到下次选瓶
```

以 **1000 ml、流速 10 ml/s** 为例：

| | 计算 | 总时长 |
| --- | --- | --- |
| 开机后第一次 | `5 + 1 + (1+8+1) + 100 + 3 + (1+8+1)` | **129 秒** |
| 之后每次 | `5 + (1+8+1) + 100 + 3 + (1+8+1)` | **128 秒** |

`WS_VALVE_DELAY`（默认 5s）是选完瓶后等电磁阀动作到位的时间，**不管选 1 号瓶还是
2 号瓶都要等**。

\* **第 ③ 步只在开机后第一次采样做**：采样杆的电机驱动器**每次上电后，在收到过
一次“收回”指令之前，会忽略“伸出”指令**。表现就是 —— **只要不断电，开机后第一次
采样放杆没反应，第二次以后全部正常；断电重启必然重现。** 所以第一次采样前先用
`WS_ROD_HOME`（默认 1s）的“收回”脉冲帮它回零。杆本来就在上限位，这个脉冲不会
让它移动。设成 `0` 可以关掉这一步。

`WS_OPEN_TIME` / `WS_CLOSE_TIME` 只是**行程时间**，前后的 `WS_ROD_GUARD`（默认 1s）
是单独加的保护时间，用来吃掉电机驱动器的启动和停止延迟。前后各 1s 内电机收
`1500`（停止），只有中间那 8s 才给动作 PWM。

每一步飞控都会发一条 `STATUSTEXT`：

| 时机 | 文本 |
| --- | --- |
| 触发瞬间（①） | `WS: bottle 2 1000ml selected` |
| ②③ 结束、开始放杆（④） | `WS: rod lowering` |
| 放杆到位、开始抽水（⑤） | `WS: pumping 100s` |
| 容量抽够、停泵（⑥） | `WS: volume reached` |
| 开始收杆（⑧） | `WS: rod retracting` |
| 收杆完成（⑨） | `WS: sample complete` |

请求被拒绝时飞控**一个机构都不动**，只发一条告警：

| 文本 | 原因 |
| --- | --- |
| `WS: volume channel %d is not available` | 容量信箱通道号非法 |
| `WS: no volume selected on channel %d` | 容量信箱读到 0（地面站没写）|
| `WS: %uml exceeds the %dml limit` | 容量超 `WS_MAX_VOLUME` |
| `WS: WS_FLOW_RATE must be positive` | `WS_FLOW_RATE` ≤ 0 |

所有文本都短于 50 字符，不会分片。

> ⚠️ **触发是上升沿，不是高电平**。所以地面站必须每次都把触发通道拉回
> `1500` 或以下，否则下一次点"开始"不构成上升沿，不会触发。
>
> 采样进行中再按"开始"**不起作用**（飞控只在空闲时接受触发）。
>
> 参数不合法时飞控**一个机构都不动**，只发一条告警说明原因。
> **注意此时 `COMMAND_ACK` 仍回 `ACCEPTED`**，
> 所以地面站不能靠它判断是否真的开始采样。

### 两块板子的通道对照

两个板子用**同一份代码**，靠各自的 `defaults.parm` 区分：
`libraries/AP_HAL_ChibiOS/hwdef/SIYI_N7/defaults.parm` 与 `.../SkyDroid-S3/defaults.parm`。

| 用途 | SIYI N7 | SkyDroid-S3 |
| --- | --- | --- |
| 采样杆电机 | AUX1 / `SERVO9` / GPIO 50 | PWM6 / `SERVO6` / GPIO 55 |
| 电磁阀 | AUX2 / `SERVO10` / GPIO **51** | PWM2 / `SERVO2` / GPIO **51** |
| 水泵正转 | AUX3 / `SERVO11` / GPIO 52 | PWM4 / `SERVO4` / GPIO 53 |
| 水泵反转 | AUX4 / `SERVO12` / GPIO 53 | PWM5 / `SERVO5` / GPIO 54 |
| `SERVO_GPIO_MASK` | `3584` | `26` |

> N7 有 IOMCU，FMU 输出从 `SERVO9` 开始；S3 没有，所以是 `SERVO1`～`SERVO12`。
> S3 上 `SERVO1` 是转向、`SERVO3` 是油门（Rover 默认），两者都不能占用。

> **关于 `WS_TRIG_CHAN`（触发"信箱"）**：它只是一个通道**编号** —— 地面站把值写进 `SERVOn`，
> 驱动**只读取这个值**，不需要对应引脚做任何事。例如 `WS_TRIG_CHAN = 10` 只借用 `SERVO10` 这个名字，
> AUX2 引脚本身是空着的。
>
> 但要注意：`SERVOx_FUNCTION = 0` 的官方含义是"**通用 PWM 输出**"（给 `DO_SET_SERVO` 用），
> 不是"关闭的引脚"。**一旦往这个通道写过值，它的物理引脚上就会出现 PWM 波形**。
> 所以**不要把这个引脚再拿去当 GPIO 用**（比如做水泵这样的开关量输出）——
> 要那样用，请先确认 `SERVOx_FUNCTION = 0` 且把 `WS_TRIG_CHAN` 改到一个**没有物理引脚**的通道号
> （例如 15），把该引脚彻底空出来。

## 接线

```
采样杆：
飞控 SERVO9 信号线 ──► 电机驱动器 PWM 输入
驱动器电源        ──► 独立电源（不要用飞控的舵机供电）
飞控 GND          ──► 驱动器 GND（必须共地）

电磁阀（AUX2）：
飞控 AUX2 ──► 继电器模块控制输入端
继电器触点 ──► 24V 电磁阀线圈（必需独立电源）
飞控 GND ──► 继电器模块 GND（必须共地）

水泵（AUX3 / AUX4）：
飞控 AUX3 ──► 正转信号线
飞控 AUX4 ──► 反转信号线
水泵电源 ──► 独立 24V 电源
飞控 GND ──► 水泵控制板 GND（必须共地）
```

`SERVO14` / `SERVO15` / `SERVO16`（开始 / 瓶号 / 容量信箱）**空着不接**，
它们只是地面站下命令用的"信箱"，没接任何设备。

> ⚠️ **接线前先量一下水泵信号线的类型**：万用表**电阻档**量信号线对控制板 GND，
> 有内部上拉（几 kΩ ~ 几十 kΩ）就是拉低触发的光耦/三极管输入，可直连；
> 若是 24V 电平输入，**必须加继电器/光耦隔离**，直连会烧飞控。

## 地面站（QGC）对接

核心只有一条 MAVLink 命令：

```
先写瓶号：  MAV_CMD_DO_SET_SERVO   param1 = 15   param2 = 1900（2号瓶）/ 1500（1号瓶）
再写容量：  MAV_CMD_DO_SET_SERVO   param1 = 16   param2 = 1000（毫升）
最后开始：  MAV_CMD_DO_SET_SERVO   param1 = 14   param2 = 1900（上升沿）
```

驱动检测到触发通道出现 **上升沿**（从 ≤1500 变到 >1500）就启动一次采样。
连续按住不会重复触发，开机时如果通道已经是高电平也不会误触发。

⚠️ **所以每次采样前必须先"松手"**：一次采样结束后触发通道会停在 `1900`，
不先发一个 ≤1500 的值回去，第二次再发 `1900` 不构成上升沿，不会触发。

```
第一次采样：  直接发 (通道 14, 1900)
第二次以后：  先发 (通道 14, 1500) 松手，再发 (通道 14, 1900)
```

**建议在 QGC 侧自动完成"松手"，用户只需单击一次**：按下时发 `1900`，
**200 ms 后自动补发 `1500`**。

这样做是安全的 —— 采样启动后 10 秒时序完全由飞控内部计时驱动，触发通道的值在
下次边沿到来前不再被读取；而且触发通道（14）与电机通道（9 / 6）是两个不同通道。
所以复位 `1500` **不会打断**正在进行的采样，只是把"信箱"清空。

```
按下 → (通道 14, 1900) → 200ms → (通道 14, 1500)
```

通道号由 `WS_BOTTLE_CHAN` / `WS_VOLUME_CHAN` / `WS_TRIG_CHAN` 决定，默认 15 / 16 / 14。

三个信箱通道（14 / 15 / 16）和采样杆电机通道（`WS_MOTOR_CHAN`）的 `SERVOx_FUNCTION`
都必须是 **0（Disabled）**，否则 ArduPilot 会拒绝命令并回报
`ServoRelayEvent: Channel N is already in use`。

### 上电后建议这样测

1. 先确认采样杆那路 `SERVOn_FUNCTION = 0`（默认就是 0，不用改）
2. 用手动方式给**通道 9** 发 `1100` → 这是"伸出"方向；发 `1900` 是"收回"方向；`1500` 停止
   （这一步同时验证了"AUX1 就是 SERVO9"）
3. 方向反了，就把 `WS_OPEN_PWM` 和 `WS_CLOSE_PWM` 对调
4. 再按上面的方法发 183 命令，走一遍完整的时序

> 具体按钮入口随 QGC 版本而不同：凡是能发送自定义 MAVLink 命令的地方都可以用
> （QGC 的自定义动作、Mission Planner 的 Servo/Relay 页面、或任何 MAVLink 命令行工具）。
> 需要的只是那条 `DO_SET_SERVO`。

**没有收到任何命令时**：杆通道从开机起就一直输出 `1500`（**停止**），杆一下都不会动。

之所以要这样，是因为有些电机驱动器**在还没收到过有效信号时，会直接忽略第一条动作指令**。
以前版本开机完全不输出，结果就是**第一次采样的第一次"放杆"完全没反应**（而之后的收杆却正常，
因为那时驱动器已经连续看到了一百多秒的中立信号）。现在开机就把通道稳在 `1500`，
既不会让杆动，又让驱动器始终有信号。

## 与水质传感器的关系

两者互相独立：

- 水质传感器用 `WQ_SERIAL` / `SERIALx_PROTOCOL = 51`，走串口；
- 采样杆只用舵机输出，不碰串口。

采样杆**不会**自动触发水质测量；如果需要"伸出 → 稳定 → 测量 → 收回"，请在地面站侧按时间编排。

## 故障排查

| 现象 | 检查 |
| --- | --- |
| 按"开始"没反应 | `WS_ENABLE`=1？触发通道两次之间回过 1500 吗（要上升沿）？`SERVO14_FUNCTION`=0？地面站确实发出了 183 命令？ |
| 发了命令但机构都不动 | 看 STATUSTEXT：很可能是容量为 0 或超 `WS_MAX_VOLUME`（**这种情况 `COMMAND_ACK` 仍回 ACCEPTED**）|
| 电机（采样杆）不动 | `WS_MOTOR_CHAN` 与本板子实际输出号对不对（S3 是 6，不是 9）？电机那路 `SERVOn_FUNCTION`=0？ |
| **只有第一次采样的第一次"放杆"没反应**（收杆正常） | v9 及以前的问题，v10 已修：驱动器在收到过有效信号前会忽略第一条动作指令。v10 起开机就把杆通道稳在 `1500`，详见上面"没有收到任何命令时" |
| **整段采样里 PWM 通道（采样杆）没输出，但 GPIO（泵、阀）正常** | 检查 `BRD_SAFETY_DEFLT`：N7 有安全开关引脚，该参数默认是 `1`，会**屏蔽全部 FMU 的 PWM 输出**但**不影响 GPIO**。改成 `0` 重启 |
| **泵和阀完全不动，量引脚恒为 0V** | **`SERVOn_FUNCTION` / `SERVO_GPIO_MASK` 没设对** —— 引脚仍归 PWM 定时器，`hal.gpio->write()` 被静默丢弃。改完**必须重启** |
| 电磁阀选反了 | 把 `WS_VALVE_ACTLOW` 反过来（`1` ↔ `0`）|
| 杆方向反了 | 对调 `WS_OPEN_PWM` 和 `WS_CLOSE_PWM` |
| 抽水量不对 | 标定 `WS_FLOW_RATE`：实测抽一定时间的量，算出真实的 ml/s |
| 泵还在转阀还在吸合就把杆收回去了 | 增大 `WS_CLOSE_DELAY` |
| 怀疑采样机构导致异常 | **把 `WS_ENABLE` 设为 0 重启**，采样杆即完全静默（泵和阀有各自的开关键）|

# 水泵驱动（AP_WaterPump）

水泵和采样杆**共用同一个参数组前缀 `WS_`**，但**互相独立** —— `WS_ENABLE` 关掉采样杆**不影响水泵**
（水泵有自己的 `WS_PUMP_ENABLE`）。

## 硬件

24V 水泵自带控制板，两根信号线，**低电平触发**，分别控制正转（吸水）和反转（吐水）：

| 信号线 | 拉低时 | 飞控引脚（N7 / S3）|
| --- | --- | --- |
| 正转（吸水）| 吸水 | `GPIO(52)` = **AUXOUT3** |
| 反转（吐水）| 吐水 | `GPIO(53)` = **AUXOUT4** |
| 两根都为高 | 停止 | — |

⚠️ **接线前务必先确认信号线类型** —— 万用表**电阻档**量信号线对水泵控制板 GND：

- 有内部上拉（几 kΩ ~ 几十 kΩ）→ 拉低触发的光耦/三极管输入 → **可直连飞控，必须共地**
- 若是 24V 电平输入 → **必须加继电器/光耦模块隔离**，直连会烧飞控

⚠️ **建议两根信号线各加一个上拉电阻到 3.3V**。从飞控上电到主循环开始驱动引脚之间有约 1 秒窗口，
这段时间引脚状态不确定。固件会在第一次 `update()` 时立刻把两路都置为"不触发"，但**硬件上拉更可靠**。

## 参数

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `WS_PUMP_ENABLE` | `1` | 总开关。置 0 会**强制停止**，两路都保持高电平 |
| `WS_PUMP_FWD_PIN` | `52` | 正转（吸水）输出的 GPIO 编号，52 = AUXOUT3 |
| `WS_PUMP_REV_PIN` | `53` | 反转（吐水）输出的 GPIO 编号，53 = AUXOUT4 |
| `WS_PUMP_CMD_CH` | `13` | 命令通道 `SERVO13`，**不接线** |

`WS_PUMP_FWD_PIN` / `WS_PUMP_REV_PIN` 改动后**需要重启**。

⚠️ **这两路必须标记为 GPIO，只把 `SERVOn_FUNCTION` 设成 0 是不够的**：

```
SERVO_GPIO_MASK = 3072      # N7：bit10(Servo11, AUX3) + bit11(Servo12, AUX4)
```

或等价的 `SERVO11_FUNCTION = -1` + `SERVO12_FUNCTION = -1`。

**原因**：`SERVOx_FUNCTION = 0` 的官方含义是"**通用 PWM 输出**"，引脚仍然归 PWM
定时器所有（定时器输出值 0 → 0V）。驱动用的是 `hal.gpio->write()`，它只在引脚被
标记为 GPIO 时才生效，否则**静默什么都不做**。

**症状**：水泵完全不动，万用表量两路输出**恒为 0V**（停止时本应是 3.3V），
而且**没有任何报错**。

> **SkyDroid-S3 不适用上面的值**。该板子没有 IOMCU，12 路输出是 `SERVO1`~`SERVO12`，
> 且 `SERVO1` 是 Rover 的转向、`SERVO3` 是油门，不能占用。
> S3 的完整取值见下面 §两块板子的通道对照，
> 已随固件打包在 `libraries/AP_HAL_ChibiOS/hwdef/SkyDroid-S3/defaults.parm`。

## 地面站对接（三个按键）

三个按键都往**同一个命令通道**（`WS_PUMP_CMD_CH`，默认 13）写一个值：

| 按键 | 发送的命令 | 效果 |
| --- | --- | --- |
| **正转** | `MAV_CMD_DO_SET_SERVO` → `param1 = 13`，`param2 = 1900` | 正转（吸水）|
| **反转** | `MAV_CMD_DO_SET_SERVO` → `param1 = 13`，`param2 = 1100` | 反转（吐水）|
| **停止** | `MAV_CMD_DO_SET_SERVO` → `param1 = 13`，`param2 = 1500` | 停 |

**方向是锁存的**：点一次就一直转，直到点"停止"或点另一个方向。**重复点同一个键也有效**
（驱动读的是通道的**值**而不是上升沿）。

判据（`WS_PUMP_CMD_*`）：`≥1800` 正转 ／ `1000~1200` 反转 ／ 其它（含 0 和 1500）停止。
开机时通道还没被写过，读到 0 → 停止 ✓

## 互锁

**正转和反转不可能同时有效**：整个驱动只保存**一个方向变量**，`apply_mode()` 由它决定
"一路拉低、另一路拉高"，所以两根信号线**永远不会同时为低** ✓

⚠️ **断链不会停泵**：水泵是锁存的，链路中断后会按最后一条命令**继续运行**。
这是刻意设计（断链不应中断作业）。若业务上需要"失联即停泵"，必须由地面站侧
定时续发命令实现 —— 飞控侧没有链路看门狗。

## 上电后建议这样测

1. 先把水泵两路标记为 GPIO（**不是** `0`）：`SERVO_GPIO_MASK = 3072`（N7），
   或 `SERVO11_FUNCTION = -1` + `SERVO12_FUNCTION = -1`，然后**重启**
2. 万用表量 AUX3 / AUX4 对 GND，**不操作时都应是 3.3V** —— 若为 0V 说明第 1 步没生效
3. 给**通道 13** 发 `1900` → 应为"吸水"方向（AUX3 变 0V）；发 `1500` 停
4. 给**通道 13** 发 `1100` → 应为"吐水"方向（AUX4 变 0V）；发 `1500` 停
5. 方向反了，把 `WS_PUMP_FWD_PIN` 和 `WS_PUMP_REV_PIN` 对调（或在硬件上对调两根线）
6. 反复点"正转 / 反转 / 停止"，确认**每次点击都立刻生效** ✓
